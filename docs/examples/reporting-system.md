# Синтетический BRD: система формирования отчётности

Все системы, правила и характеристики ниже вымышлены. Вводные заданы полностью для выбранного сценария; уточняющий диалог не моделируется. Это вход для [ручного эталона результата](reporting-system/expected-result.md).

## Назначение и границы

Аналитик получает сводку продаж по подразделениям за выбранный день и скачивает её в CSV. В проект входят получение данных, хранение дневных срезов, формирование сводки и выдача файла через браузер.

Источники данных, корпоративный сервис доступа и платформа PostgreSQL уже существуют. Их разработка, рассылка отчётов, изменение продаж и создание новых ролей не требуются. Все даты и расписания используют UTC. Денежные суммы заданы в одной условной валюте с двумя знаками после запятой.

## Требования

| ID | Требование |
| --- | --- |
| R-01 | Каждый день в 06:00 загружать полный срез продаж и подразделений за предыдущий календарный день; опубликовать его до 06:15 |
| R-02 | Хранить последние 30 календарных дней. Публиковать продажи и подразделения одного дня атомарно; повторная загрузка того же дня заменяет срез без дублей |
| R-03 | Аналитик выбирает день и видит только подразделения с продажами: наименование, количество продаж и сумму. При отсутствии опубликованного среза за день показывать «Данные не загружены» |
| R-04 | Аналитик скачивает ту же сводку в CSV с колонками date, unit_name, sale_count, total_amount. При пустом срезе файл содержит только заголовок |
| R-05 | При недоступности источника, повторяющемся sale_id или неизвестном unit_id новый срез не публикуется. Существующие срезы сохраняются; пользователь видит состояние последней загрузки и доступные даты |
| N-01 | До 5 000 продаж за день, до 20 подразделений и 10 одновременных аналитиков. Целевое время выдачи сводки или CSV — не более 5 секунд |
| N-02 | Доступность в рабочие дни с 08:00 до 18:00 — 99,5%; целевое восстановление — до 4 часов, допустимая потеря данных — до 24 часов |
| N-03 | Все передаваемые и сохраняемые данные относятся к внутренним данным компании. Персональных данных нет. Просмотр и скачивание разрешены только с действующим токеном и ролью analyst |

На первом запуске загружается один предыдущий день; историческая загрузка не требуется. Очистка удаляет срезы старше 30-дневного окна. Пустой ответ продаж является корректным срезом, неизвестное подразделение — ошибкой. Расчёт ресурсов и доказательство выполнения временных показателей в этот пример не входят.

## Данные

| ID | Набор | Состав и условия |
| --- | --- | --- |
| D-SALES | Продажи | sale_id, sale_date, unit_id, amount; идентификаторы уникальны внутри дня |
| D-UNITS | Подразделения | unit_id, unit_name; содержит все подразделения, на которые ссылаются продажи выбранного дня |
| D-SNAPSHOT | Опубликованный срез | D-SALES и D-UNITS за один день; используется для повторяемого формирования сводки |
| D-REPORT | Сводка | date, unit_name, sale_count, total_amount; сумма amount и число продаж по каждому подразделению |
| D-ACCESS | Результат проверки доступа | active и роли; предоставляется корпоративным сервисом, не сохраняется в хранилище отчётов |

## Корпоративный контекст

Пользователь получает токен на существующей странице корпоративного входа до обращения к приложению. Приложение проверяет active и analyst при каждом пользовательском запросе, включая доступные даты и состояние загрузки. Сервис доступа самостоятельно проверяет срок и подлинность токена; при его недоступности пользовательский запрос отклоняется.

| Объект | Готовая возможность |
| --- | --- |
| SYS-SALES — «Продажи» | GET /exports/sales?date=…; HTTPS, порт 443, JSON D-SALES; полный завершённый срез готов к 05:45; доступ сервисной учётной записи только на чтение |
| SYS-UNITS — «Подразделения» | GET /exports/units?date=…; HTTPS, порт 443, JSON D-UNITS; согласованный с продажами срез готов к 05:45; доступ только на чтение |
| SYS-IAM — «Корпоративный доступ» | POST /token/introspect; HTTPS, порт 443, JSON D-ACCESS; приложение аутентифицируется сервисной учётной записью |
| DB-REPORTS — платформа PostgreSQL | Выделенная логическая БД, PostgreSQL поверх TLS, порт 5432; запись и чтение только учётной записью приложения. По каталогу платформа рассчитана на заданный объём, выполняет ежедневные резервные копии и поддерживает восстановление до 4 часов с потерей до 24 часов |
| Платформа приложений | HTTPS на порту 443, хранение секретов и запуск встроенной задачи по расписанию; отдельный сервис-планировщик не нужен |

Все учётные данные выдаёт платформа; секретные значения в документах отсутствуют.

## Правила контекста

| ID | Правило |
| --- | --- |
| SEC-01 | Все соединения защищены TLS; используются только протоколы и порты из каталога выше |
| SEC-02 | Приложение проверяет доступ для просмотра и скачивания; источники не вызываются непосредственно из браузера |
| SEC-03 | Источники доступны приложению только на чтение; токены и содержимое отчётов не записываются в журналы |
| ARCH-01 | Переиспользуются доступные корпоративные сервисы; новые БД-платформы и сервисы доступа не создаются |
| ARCH-02 | Ночная загрузка вне пользовательского времени может выполняться в одном приложении с веб-интерфейсом |
| VIEW-01 | В представлении данных используются Application Component и Data Object, отношения Flow и Access. В техническом представлении — Application Component, System Software и направленная Association с подписью протокола; направление Association означает инициатора обращения |

Исключения из этих правил отсутствуют. Контекст и этот BRD составляют весь набор вводных данного примера. Конкретные адреса серверов, программные классы и физическая инфраструктура не требуются для выбранного уровня проектирования.

Идентификатор редакции BRD и включённого корпоративного контекста: `reporting-input-1`.
