# Приложение А.1. Текстовое описание требований к входящим артефактам (BRD)

Для обеспечения высокой точности извлечения требований (FR-01), сквозной трассируемости (FR-09) и корректного анализа изменений при обновлении версий (FR-12) входящие документы с бизнес-требованиями должны соответствовать следующим рекомендациям:

1. Метаданные и версионирование: Каждый документ должен содержать уникальный идентификатор, номер редакции (версии) и дату утверждения. Это позволяет системе фиксировать неизменяемую версию источника при привязке архитектурных решений и корректно вычислять разницу (Diff) при загрузке обновлённого файла.

2. Сквозная идентификация элементов: Все ключевые сущности внутри документа (бизнес-цели, роли, функциональные и нефункциональные требования, наборы данных, ограничения) должны иметь уникальные текстовые коды (например, FREQ-01, DATA-01, NFR-01). Это исключает неоднозначность при цитировании и упрощает навигацию архитектора от диаграммы к первоисточнику.

3. Чёткое разделение границ ответственности (Scope): В документе должны быть явно разграничены функции, реализуемые внутри проектируемой системы, и функции, остающиеся на стороне внешних систем или пользователей. Это предотвращает ошибки топологии графа («чёрные дыры» и «чудеса» по FR-07).

4. Структурированное описание данных: Сведения о передаваемой информации должны быть сведены в единый реестр с указанием отправителя, получателя, состава ключевых атрибутов, класса конфиденциальности (например, ПДн, коммерческая тайна) и периодичности передачи.

5. Выделение архитектурно значимых NFR и ограничений: Требования к доступности (SLA), пиковым нагрузкам (RPS), окнам пакетной обработки, шифрованию каналов и запретам на использование определённых технологий должны быть описаны в отдельных разделах с привязкой к конкретным функциям или потокам данных.

6. Отсутствие скрытых инструкций: Текст документа должен содержать исключительно описание предметной области и требований; любые директивы, имитирующие системные команды для ИИ, игнорируются системой безопасности.

Эти рекомендации служат эталоном подготовки входных BRD и не запрещают анализ иных документов MVP. Неоднозначные соответствия требований между редакциями при анализе изменений подтверждает архитектор.
