# Редактируемые документы и PDF

В репозитории хранятся пять готовых PDF-версий и их редактируемые исходники LaTeX:

| Документ | PDF | LaTeX |
| --- | --- | --- |
| Бизнес-требования MVP | [brd.pdf](pdf/brd.pdf) | [brd.tex](latex/brd.tex) |
| Сквозной пример системы отчётности | [example.pdf](pdf/example.pdf) | [example.tex](latex/example.tex) |
| Ключевые технические решения | [technical-decisions.pdf](pdf/technical-decisions.pdf) | [technical-decisions.tex](latex/technical-decisions.tex) |
| Приложение А.1: требования к входящим артефактам | [brd-input-guidelines.pdf](pdf/brd-input-guidelines.pdf) | [brd-input-guidelines.tex](latex/brd-input-guidelines.tex) |
| Приложение А.2: эталонный шаблон BRD | [brd-template.pdf](pdf/brd-template.pdf) | [brd-template.tex](latex/brd-template.tex) |

Второй документ разделён на исходные требования, синтетический корпоративный контекст и ожидаемый архитектурный результат. Он включает обе диаграммы, решения и результаты проверок. Для чтения PDF другие файлы не требуются. Текст доступен для поиска и копирования; диаграммы сохраняются в векторном виде.

## Правки и сборка

Редактируйте пять файлов `docs/latex/*.tex` напрямую. Общие шрифты, цвета, поля и оформление находятся в [common.tex](latex/common.tex). Затем из корня репозитория выполните:

```sh
python3 scripts/build_documents.py
```

Обычная сборка **не перезаписывает LaTeX** и сохраняет ручные правки. Сборка преобразует актуальные SVG-диаграммы во временные PDF и компилирует каждый документ минимум дважды, до совпадения `.aux`/`.toc`/`.out` (максимум четыре прохода; отсутствие сходимости останавливает сборку). Машиночитаемые файлы не читаются издателем и не требуются для компиляции PDF; их проверяет отдельный валидатор эталона. Результат сохраняется в `docs/pdf/`; временные файлы и журналы — в игнорируемом `.build/documents/`. Ошибки компиляции, отсутствующие символы и выход текста за поля останавливают сборку.

Markdown остаётся самостоятельной редактируемой версией документации. Синхронизация текста Markdown и LaTeX выполняется явно. Если после изменения Markdown нужно заново получить LaTeX, выполните:

```sh
python3 scripts/build_documents.py --refresh-tex
```

**Эта команда перезаписывает все пять LaTeX-исходников, включая ручные правки в них.** `common.tex` сохраняется. Перед обновлением сохраните нужные правки в Git и проверьте полученный diff. В этой редакции текст не скрывается по старым жёстко заданным фразам: вводные, ограничения и статус эталона публикуются из Markdown. Источники регенерации: `docs/BRD.md`, `docs/examples/reporting-system.md`, `docs/examples/reporting-system/expected-result.md`, [technical-decisions-summary.md](technical/technical-decisions-summary.md), [brd-input-guidelines.md](brd-input-guidelines.md) и [brd-template.md](templates/brd-template.md). Относительные ссылки превращаются в понятные подписи; диаграммы включаются в документ, машинная модель остаётся в репозитории. Общие правила сохраняются после регенерации:

- `DocumentTitle` размещает заголовок, назначение (если задано) и компактное оглавление на первой странице, затем начинает основной текст с новой страницы. Отдельной пустой титульной страницы нет. BRD использует оглавление первого уровня, Example — двух уровней; технический обзор переносит вступление из Markdown на первую страницу.
- Профили в `refresh()` задают разрывы перед частями II/III примера и перед Backend, искусственным интеллектом и пользовательским интерфейсом технического обзора. BRD не получает разрыв перед каждым разделом. Это смысловые границы, а не привязка к номерам страниц.
- Таблицы до четырёх строк измеряются целиком; для больших измеряются шапка и две начальные строки. `KeepTableStart` резервирует место вместе с непосредственно предшествующим заголовком, не более половины высоты страницы для необычно высоких строк. Сама таблица остаётся `longtable`, свободно продолжается и повторяет шапку.
- Короткий список с соседним заголовком/краткой вводной измеряется один раз. Блок до 32% высоты страницы переносится целиком; длинный остаётся разбиваемым. Во время измерения отключены проверки места заголовка, чтобы они не вносили ложные разрывы из внешней страницы.
- Шрифты с кириллицей, поля, цвета, удержание заголовков и нумерация общие. Основной текст BRD/Example — 10 pt, краткого технического обзора — 11 pt; экономия страниц уменьшением шрифта не применяется. Оглавление имеет ссылки на разделы, PDF содержит закладки.

Технический PDF ограничен пятью A4: первая страница и четыре смысловые части. BRD и Example не имеют искусственного лимита страниц. После изменения источников необходимо проверить итоговые номера оглавления, каждую страницу, короткие списки, продолжения таблиц, русские символы, ссылки/закладки и обе векторные диаграммы. Успешная компиляция не заменяет визуальную проверку.

Перед сборкой после изменения `.puml` пересоздайте обе SVG из исходников. Для текущего комплекта использован PlantUML 1.2026.9 и Graphviz; например, с локальным JAR:

```sh
java -Djava.awt.headless=true -jar /path/to/plantuml-1.2026.9.jar -charset UTF-8 -tsvg docs/examples/reporting-system/data-flow.puml docs/examples/reporting-system/interactions.puml
python3 scripts/build_documents.py --refresh-tex
```

Обычная PDF-сборка использует сохранённые SVG и сама не запускает PlantUML. После пересборки проверьте таблицы, переносы и обе диаграммы визуально; экспорт кода `.puml` обязателен для A-03 (диаграмма потоков данных) и A-05 (диаграмма межсистемных взаимодействий).

## Инструменты

Нужны Python 3, XeLaTeX, Inkscape и шрифты DejaVu с поддержкой кириллицы. Pandoc требуется только для `--refresh-tex`.

Для Ubuntu/Debian:

```sh
sudo apt-get update
sudo apt-get install -y texlive-xetex texlive-latex-extra texlive-lang-cyrillic texlive-fonts-recommended fonts-dejavu inkscape
# Только для регенерации LaTeX из Markdown:
sudo apt-get install -y pandoc
```

Для временных меток используется `SOURCE_DATE_EPOCH`, а если он не задан — время последнего коммита базовых BRD/примера и их LaTeX-исходников (без `docs/pdf/`). Это уменьшает лишние изменения PDF при одинаковых исходниках и версиях инструментов. Побайтовая идентичность между разными версиями TeX, шрифтов и Inkscape не гарантируется.

## Автоматическая сборка

[GitHub Actions](../.github/workflows/build-pdf.yml) компилирует существующие LaTeX-исходники и публикует все пять PDF из `.build/document-artifacts/` как артефакт запуска, не перезаписывая версии в `docs/pdf/`. Регенерация из Markdown в CI не выполняется, поэтому ручные правки LaTeX сохраняются.

Workflow выполняет сборку и загружает артефакты без записи в Git. Обновлённые PDF включаются в тот же проверенный коммит, что и исходники; сборка не создаёт дополнительных коммитов в ветке PR. Одновременные сборки одного PR отменяют устаревшие запуски.

## Проверки эталона и издателя

```sh
python3 -m pip install -r scripts/requirements-docs.txt
python3 scripts/validate_example.py
python3 -m unittest discover -s scripts -p 'test_*.py'
```

Отдельный валидатор проверяет JSON-синтаксис (включая дубликаты и недопустимые константы), JSON Schema Draft 2020-12 с UUID formats, глобальную уникальность ID, типы/целостность ссылок, дерево папок и состав видов, повторное использование общих объектов. Он сверяет source SHA-256/size/version/раздел и соответствие узлов, направлений и read/write в PlantUML/видах, узлов/соединений/подписей SVG исходникам. Проверки относятся к этому документарному эталону, а не к ещё не реализованным доменным классам, допустимым операциям и инвариантам приложения. Их проектирование и round-trip сериализации — последующие PR.

Regression-тесты проверяют повреждённые ссылки, дерево, версии, ID, диаграммы, формализованные статусы, отсутствие JSON-листинга, наличие третьего LaTeX-исходника, профили оглавлений/смысловых разрывов, вложенные списки, измерение компактных/длинных таблиц и отсутствие наложения измеряемого списка на предыдущий абзац (XeLaTeX + `pdftotext` из Poppler). CI выполняет отдельный валидатор и тесты перед компиляцией; издатель больше не создаёт JSON-приложение и не связан с проверкой данных. Исходники машинной модели и JSON Schema остаются отдельными файлами репозитория.

Обычная сборка сохраняет ручные изменения LaTeX и не требует Pandoc; `--refresh-tex` явно обновляет текст из Markdown. При изменении входного документа source version/hash/size обновляются осознанно; иначе валидатор, а не PDF-издатель, останавливает CI. В текущем комплекте LaTeX регенерирован из актуального Markdown; повторный refresh проверяется локально сравнением файлов.

Для проверки CI-сборки без записи в `docs/pdf/` используйте `python3 scripts/build_documents.py --output-dir .build/document-artifacts`.

CI использует Python 3.13 и дополнительно проверяет, что обычная сборка не изменила `docs/latex/`. Ни один шаг не выполняет commit/push.

Для визуальной проверки можно использовать `pdftoppm -scale-to 1400 -png docs/pdf/brd.pdf .build/documents/brd` и аналогично для example. Проверяются все страницы, переносы/повтор шапок, кириллица, обе диаграммы и отсутствие JSON-листинга; успешная компиляция сама по себе не подтверждает читаемость.
