# PR 2: чек-лист замечаний к backend

Дата: 27 ноября 2026. Проверен текущий PR 2 с сохранением изменений предыдущего
этапа ревью. Изменения не публиковались и не сливались.
Отметка означает, что пункт разобран; сохранённые решения и причины отказа указаны явно.

## Имена и структура

- [x] `self.files_storage`, `self.document_parser`, `staged_file` вместо общих имён.
- [x] `DocumentProvider.files_storage()` и `.document_parser()`; явное имя
  `requirements_extraction_agent` в DI и зависимостях этапов.
- [x] Методы документов: `get_parsed_document`, `get_upload_operation`,
  `recover_uploads`, `attach_document`, `list_attachments`, `get_version`, `list_versions`.
- [x] `DocumentService` находится в `application/services/document_service.py`.
  Это оркестратор файлового хранилища, парсинга и БД. Название repository и перенос
  в persistence скрывали бы его реальную ответственность.
- [x] `RequirementsExtractionService` управляет запусками, историей и отменой.
  Название `DocumentExtractor` не отражало бы эти операции; извлечение выполняет агент.
- [x] `ExtractionContextBuilder` именно строит бюджетированный контекст, а не
  извлекает требования. Поэтому оставлен Builder вместо ContextExtractor.
- [x] `StructuredOutputGenerator` вынесен в одноимённый модуль.
- [x] Интерфейсы находятся в `application/protocols/*_protocols.py`; ports-файлов нет.
- [x] В application выделены `models`, `errors`, `prompts`, `protocols`, `agents`,
  `context`, `services`, `validation`, `workflows`.
- [x] В infrastructure выделены `parsers` и `storage/local_files_storage.py`;
  в persistence — `documents` и `extractions`. Небольшие domain, presentation,
  config и DI не раздроблены на дополнительные однофайловые пакеты.
- [x] Функции преобразования/проверки результатов отделены от агента;
  `merge_parts` переименована в `merge_extraction_results` и вынесена отдельно.
- [x] Предпочтения обобщены в корневом `AGENTS.md`.
- [x] Явные аннотации локальных переменных сохранены по подтверждённому решению пользователя.
- [x] Асинхронные генераторы ресурсов, lifespan и фабрики аннотированы
  `AsyncGenerator`; входные асинхронные итераторы оставлены `AsyncIterator`.

## Документы и восстановление

- [x] `upload_digest` и `parse_digest` отделены от оркестратора. Дайджест загрузки
  формируется из нормализованной команды и `staged_file`.
- [x] Общее чтение версии и проверка содержимого вынесены в `_load_version_content`.
- [x] Чтение оригинала при попадании в кэш сохранено по решению пользователя:
  сохранённый parse не должен скрывать повреждение/исчезновение источника.
- [x] `attach_document` сохраняет полную проверку целостности, чтобы не прикреплять
  существующую в БД редакцию с отсутствующим или испорченным файлом.
- [x] `recover_uploads` продолжает обработку после ожидаемых ошибок конкретной
  операции: `DocumentFailure`, недоступности БД, таймаута или файлового I/O.
  Ошибки программирования и отмена не подавляются общим `except Exception`.
- [x] После `complete` восстановление не делает повторный запрос операции:
  результат собирается из журнала и возвращённой завершённой версии.
- [x] Универсальный `_with_store(callback)` не введён: он скрывает границы
  транзакций и требует дополнительных callable/generic-обёрток. После разделения
  фаз контекстные менеджеры остаются небольшими и явными; связанные чтения
  выполняются в одной сессии.

## Контекст и извлечение

- [x] `ContextPolicy` и `ExtractionPolicy` отвергают некорректные бюджеты, отрицательные
  повторы и неположительные/нечисловые таймауты как ошибки конфигурации.
- [x] Убрана токенизация каждого растущего префикса группы: размер кандидата
  увеличивается геометрически, затем уточняется поиском. Проверки входа и выхода сохранены.
- [x] Профиль модели создаётся один раз; оценка ответа и вычисление идентичности
  выделены в отдельные модули. В payload и идентичности используются dataclasses.
- [x] Вход и пример выхода требуют разных подсчётов токенов: это не один и тот же
  текст. Дешёвая оценка выхода вместо реальной токенизации не введена.
- [x] Сохранён экспоненциальный подбор границы `longest_prefix`: поиск сразу по всей
  оставшейся длине многократно токенизировал бы заведомо огромные срезы.
- [x] Убрано специальное разрезание по точке с пробелом; остаются строки, разделители и пробелы.
  Утверждение о выходе `rfind` за maximum не подтвердилось: поиск учитывает весь delimiter.
- [x] Нарезка сохраняет `fragment_id`, `total_length` и абсолютный offset.
  Проверки полного покрытия и `total_fragments` остаются в тестах.
- [x] Введены `ExtractionContextAssembler`, `ExtractionPartExtractor`, `ExtractionFinalizer`.
  `ExtractionSteps` оставлен небольшим фасадом для графа.
- [x] Контекст переиспользуется только в пределах выполнения графа; освобождается
  при успехе, ошибке и отмене. Новый запуск и возобновление после выхода из графа
  заново проверяют исходные файлы. Изменение профиля/схемы не использует старый кэш.
- [x] Перед финальным сохранением исходники проверяются повторно без пересборки
  контекста: порча файла во время LLM-вызова не публикует успешный результат.
  Независимый ревьюер выявил этот случай, регрессия воспроизвела ошибочное COMPLETED.
- [x] Новая группировка меняет digest контекста: ранее подготовленный запуск с другим
  планом частей завершится явным `context_changed`. Исторические результаты сохраняются.
- [x] Бюджет числа частей проверяется до `store.prepare`.
- [x] Повторное бессмысленное `merge_extraction_results(parts)` удалено из шага графа.
  Потери результата не было: реальное объединение выполняется в `store.complete`.
  Промежуточный метод теперь называется `validate_completed_parts`; старое имя
  узла `merge` сохранено для checkpoint-маршрутизации.
- [x] Учёт `previous` в бюджете оставлен: каждый callback ожидается, а хранилище
  атомарно проверяет ожидаемое число запросов. Части одного запуска обрабатываются последовательно.
- [x] Проверена гонка повторной финализации: запоздавшая повторная верификация
  завершённого запуска не меняет снимок и не падает; блокировка в `complete`
  предотвращает повторную запись требований.
- [x] `StatementCategory` остаётся ограниченным подмножеством категорий без GAP и
  CONTRADICTION, но использует `RequirementCategory` в Literal вместо копий строк.
- [x] Имена узлов графа представлены `StrEnum`, состояние — dataclass, конфигурация
  thread_id типизирована. `RunnableConfig` остаётся форматом API LangGraph.

## Воркер и структурированный ответ

- [x] Диспетчер использует заданную параллельность вместо одного активного запуска.
  Общий семафор по-прежнему ограничивает суммарную работу чата и извлечения.
- [x] Маппинг ошибок вынесен в `extraction_failure_mapper`, коды явные;
  произвольный `str(error)` больше не служит резервным кодом ошибки.
- [x] `StoredExtractionCorrupt` уже наследует `ExtractionError` и попадает в
  существующий обработчик. Дополнительный дублирующий except не нужен.
- [x] Дедлайн по-прежнему отсчитывается от создания запуска, включая очередь:
  это единый бюджет времени, который нельзя сбрасывать ожиданием семафора.
- [x] Статус отмены проверяется доменной машиной состояний; завершение при штатной
  отмене и остановке процесса покрывается интеграционными проверками.
- [x] Подтверждённая отмена проверяет обе стадии через `confirm_cancellation`,
  но сохраняет только итог: двойного `set_status` в воркере больше нет.
- [x] Валидация JSON вынесена в `structured_response_validator`; попытка вызова
  модели — в `_invoke_once`.
- [x] Двойной разбор JSON сохранён: первый проход запрещает дубликаты и NaN/Infinity,
  второй использует строгую JSON-семантику Pydantic. `model_validate(strict=True)`
  для Python-словаря иначе обрабатывает UUID/даты и меняет публичный контракт.
- [x] Корректирующее сообщение не теряется: хранится в общем списке сообщений
  повторов. Неудавшийся сетевой вызов расходует запрос по назначению бюджета.
- [x] `budget.check` проверяет время/отмену, а `reserve` — число запросов;
  ветка BUDGET_EXHAUSTED достижима. Сетевые и корректирующие повторы остаются раздельными.
- [x] В `cancellable` задачи отменяются и ожидаются через gather; оставлена
  существующая семантика приоритета отмены при одновременном ответе.
- [x] LangChain splitter не добавлен: здесь существенны входной и выходной бюджеты,
  схема и резерв коррекций. Оптимизирована доменная упаковка без новой зависимости.

## Парсер и файловое хранилище

- [x] Проверка имени/MIME/сигнатуры и декодирование выделены в `DocumentValidator`.
  `parse()` переиспользует уже декодированный текст.
- [x] MarkdownIt переиспользуется экземпляром парсера; добавлен `MARKDOWN_MIME`.
- [x] Обработка заголовка проверяет наличие и тип следующего inline-токена.
  Обычный MarkdownIt формирует корректные пары; проверка защищает границу адаптера.
- [x] Расширены сигнатуры GIF, JPEG, WebP, ELF, SQLite для корректного INVALID_MIME.
- [x] Section остаётся ближайшим плоским заголовком: таков текущий контракт локатора.
  Иерархический путь был бы изменением формата сохранённых источников, а не исправлением ошибки.
- [x] Приватный `_hashlib.HASH` заменён минимальным публично типизированным протоколом хешера.
- [x] Риск EXDEV оценён: временный и конечный файл создаются под одним корнем.
  Отдельный mount для `.pending` не поддерживается. Fallback через копирование не
  добавлен, поскольку менял бы атомарную неизменяемую публикацию.
- [x] Проверка symlink уже выполнялась на исходном target/parent, а resolve
  использовался отдельно для containment. Указанного обхода здесь не найдено.
- [x] `read(size + 1)` сохранено: чтение ограничено и выявляет лишние байты, в том
  числе при гонке после stat. Замена на один предварительный stat ослабила бы проверку.
- [x] Повторное хеширование перед публикацией/чтением сохранено как проверка
  целостности; кэширование этой проверки противоречило бы согласованной гарантии.
- [x] Очистка при обычной отмене загрузки покрыта тестом. Полное завершение
  процесса/цикла событий не может гарантировать асинхронную очистку; это не повод
  подавлять CancelledError или менять все файловые операции без воспроизводимого дефекта.
- [x] Windows comparison_path сохранён с пояснением: поддержка Windows используется
  в текущем окружении и проверяется отдельными тестами.

к той же реализации без изменения поведения.
