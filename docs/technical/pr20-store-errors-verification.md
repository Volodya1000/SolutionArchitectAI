# SQL-хранилища и независимость тестов PR 20

Изменения от 28 ноября 2026 года, исходная ревизия PR — `e7fbfc0`.

## Разделение ответственности

`SqlAlchemyStoreContext[StoreT]` принимает только источник сессий и конструктор
хранилища. `SqlStoreErrorPolicy` удалён. Контекст управляет транзакцией, её
пятисекундным таймаутом и освобождением сессии. Отмена распространяется наружу.

Ошибка соединения, отключение сервера, исчерпание соединений, таймаут пула
и истечение таймаута этого контекста дают `StorageUnavailable`. Нарушения
целостности, deadlock, ошибки SQL и прочие исключения сохраняют исходный тип.
`TimeoutError` вызывающего кода не подменяется таймаутом транзакции.

Сохранённые модели проверяются непосредственно при чтении. Документы сохраняют
`DocumentFailure` с `CORRUPT_METADATA` или `CORRUPT_PARSE`; данные анализа и
уточнений — `StoredExtractionCorrupt`; данные чата и обсуждения —
`StoredDataCorrupt` с HTTP 500. Создаваемые из входа модели и входной
`ValidationError` не получают классификацию повреждения сохранённых данных.

Существующее восстановление повреждённых частей анализа сохранено. SQL-проекции
кратких результатов продолжают возвращать только метаданные. Разбор старых
TEXT-полей JSON защищён `pg_input_is_valid` и `CASE`: повреждённая запись
доходит до типизированной проверки без аварийного PostgreSQL cast.
Повреждённый вопрос консервативно блокирует свой анализ и не срывает выборку
соседних ожидающих запусков.

## Границы тестов

Общие фикстуры перенесены в `backend/tests/integration/conftest.py`, общие
конструкторы, ресурсы и подставные модели — в `backend/test_helpers`.
Именованные тесты сохранены; проверка прежней политики ошибок заменена
проверками распространения входного `ValidationError` для пяти хранилищ.

Собственный контракт import-linter сканирует Python-файлы, поскольку граф пакетов
не охватывает все пути импорта pytest. Запрещены импорты тестов и `conftest.py`
из других модулей, включая зависимости через хелперы и `tools`, относительные
импорты, `TYPE_CHECKING`, имена `tests.*` и короткие имена модулей.
Каталоги без `__init__.py` также проверяются. Фикстуры подключает pytest.

26 проверок правила воспроизводят запрещённые случаи и разрешённое использование
хелперов/фикстур. Контракт запускается из корня репозитория: этот каталог
должен быть в Python import path для `backend.*` и `tools.test_import_contract`.
Самостоятельный запуск из `backend` без настройки import path не поддерживается.

## Промпт

В `clarification_prompt.py` русский блок был добавлен к английской инструкции
в предыдущей ревизии. Теперь все инструкции изложены по-английски (`clarify-4`),
с сохранением правил дословных цитат, недоверенного контекста и языка документа
для человекочитаемых полей. Повторная смысловая приёмка реальной LLM не выполнялась;
известный блокер Qwen из предыдущего отчёта этим изменением не закрыт.

## Воспроизведение проверок

Из корня репозитория:

```powershell
uv run --locked --project backend python -m tools.quality setup
uv run --locked --project backend python -m tools.quality full
uv run --locked --project backend lint-imports --config backend/.importlinter
```

Целевые регрессии находятся в `test_store_error_classification.py`,
`test_stored_data_errors.py`, `test_store_contexts.py`, `test_stored_sql_json.py`
и `test_test_import_boundaries.py`. Обычные проверки используют fake LLM.

Ruff, Mypy, Pylint, Bandit, import-linter, WPS231, проверки frontend, сборка,

`StoredExtractionCorrupt`, затем все 217 интеграционных тестов выполнены повторно.

## Локальная демонстрация

Отдельный Compose-проект `saa-pr20-store-demo` доступен на
[localhost:8088](http://localhost:8088). Он использует fake LLM и собственные
тома PostgreSQL, файлов и Git. Подготовлены анализ с открытым вопросом и
завершённый анализ с явно сохранёнными через UI ответами. Исходные цитаты
сохранены; исходники всех 160 Python-файлов runtime сверены с рабочим деревом.

Демонстрационный проект оставлен запущенным. Изолированные проекты quality
удаляются штатным runner после проверки и не затрагивают демонстрационные тома.
