# StructuredOutputGenerator

[Навигация](README.md) · [Роли агентов](agents.md) · [RetryConfig](configuration.md#retryconfig)

`StructuredOutputGenerator` — переиспользуемый порт Application. Он принимает промпт или сообщения, идентификатор/профиль модели, Pydantic-схему результата, параметры и общий бюджет выполнения; возвращает типизированный объект либо понятную типизированную ошибку. Агент не выбирает SDK, сервер, режим JSON или число повторов. Обычный потоковый чат может использовать отдельный LLM-порт.

```text
async generate[T: BaseModel](
    prompt_or_messages, model_profile, result_schema: type[T],
    parameters, retry: RetryConfig, deadline, cancellation,
) -> T | StructuredGenerationFailure
```

**Базовый стек MVP:** `langchain-core` (сообщения, Runnable и базовые интерфейсы), `langchain-openai` (`ChatOpenAI` с явно заданным `base_url` для OpenAI-совместимого endpoint), Pydantic и собственный `StructuredOutputGenerator`. Полный пакет `langchain` не требуется для этих функций. В [документации ChatOpenAI](https://docs.langchain.com/oss/python/integrations/chat/openai#structured-output) `with_structured_output(Schema, method="json_schema")` явно выбирает native structured output; режим по умолчанию может использовать function calling. Поэтому режим задаётся явно, только после проверки поддержки конкретной пары модель/сервер и применимого подмножества схемы. Встроенный агент `create_agent` в этом дизайне не нужен.

Если сервер не поддерживает native JSON Schema, профиль может **явно** разрешить генерацию JSON-текста с последующей строгой Pydantic-валидацией. Переход виден в диагностике и не ослабляет схему. Автоматический fallback на Tool Calling, смена модели и удаление полей схемы запрещены. Поддержка OpenAI-совместимого HTTP не доказывает совместимости всех параметров. [vLLM](https://docs.vllm.ai/en/latest/features/structured_outputs/) выбран для локального контейнера; окончательные профили модели и сервера устанавливаются по интеграционным испытаниям.

LangChain и Pydantic проверяют ответ, но LangChain сам по себе не воспроизводит полный механизм исправления невалидных ответов Instructor. После ошибки JSON или схемы компонент может дать модели безопасную обратную связь и выполнить **новую генерацию** в пределах `RetryConfig`. Нельзя объявлять частичный/невалидный JSON успешным результатом. Каждый сетевой запрос, включая корректирующий, уменьшает один общий `max_total_requests`; monotonic deadline включает очередь, сеть, backoff и валидацию. Встроенные retries `ChatOpenAI`/SDK и retry policy графа для LLM-узла отключаются либо явно учитываются тем же координатором; вложенных независимых циклов у агента нет. `RetryConfig` сохраняет отдельные лимиты классов ошибок и предсказуемый backoff. Отмена немедленно завершает попытки.

Ошибки различаются по типу: сеть, rate limit (`Retry-After` внутри остатка бюджета), timeout, некорректный JSON, несоответствие Pydantic-схеме, неподдерживаемая возможность модели/сервера, отмена. Отдельно различаются пустой или обрезанный ответ, отказ модели, превышение контекста и ошибки доступа. Повтор допустим только для явно разрешённых случаев; исчерпание возвращает typed failure с безопасной диагностикой, а не фиктивный объект. Успешная Pydantic-валидация подтверждает структуру, но не истинность архитектуры: далее работают Domain-инварианты и независимое ревью.

LiteLLM и Instructor исключены из базового стека: первые два пакета LangChain закрывают нужное взаимодействие с моделью, а LangGraph выбран для оркестрации. Их можно пересмотреть при доказанных недостатках на реальных моделях. Это архитектурный выбор, **не результат испытания библиотек в приложении**.
