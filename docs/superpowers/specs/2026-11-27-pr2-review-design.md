# PR 2: требования и повторный анализ

Основание — обсуждение ревью и разрешение пользователя от 27.11.2026.
Изменения выполняются в текущей ветке PR 2; merge и публикация не входят в задачу.

## Согласованное поведение

- Интерфейс использует название «Требования» без кодов артефактов A-01–A-07.
  Навигационная цепочка различает документы и требования.
- Для подтверждённой цитаты показывается ссылка «Источник · …» и раскрываемые
  цитата и технические сведения. Предупреждение показывается для неподтверждённой
  цитаты; объяснение границ проверки и статуса кандидатов даётся один раз.
- Для уже проанализированного набора версий и области анализа основное действие —
  «Открыть результат». «Повторить анализ» создаёт отдельный запуск, сохраняя историю.
  Сообщение об одинаковых настройках показывается только после сравнения с текущим
  профилем модели и версиями контракта/промпта. Из пользовательских параметров сейчас
  доступна область анализа; модель и её лимиты задаются конфигурацией сервера.
  Для активного совпадающего запуска предлагается открыть ход анализа без дубля.
  Ошибка чтения истории не должна незаметно разрешать повторное извлечение.
- Модель сохраняет язык исходных цитат в исходной и нормализованной формулировках,
  описаниях пробелов и противоречий. Русские цитаты и английская формулировка
  отклоняются в существующей ограниченной процедуре исправления ответа.
  Технические термины на латинице допустимы. Старые результаты неизменяемы.
- Для локальной модели подбираются увеличенные контекст и резерв ответа с реальным
  smoke на BRD пользователя. Цель — обработка этого файла за один запрос, без потери
  контроля переполнения. Настройка сервера и профиль приложения согласуются.
  Оценки токенов не выдаются за измеренные значения; дробление остаётся для больших
  входов. При необходимости убираются искусственные разрывы между разделами,
  когда весь документ помещается в бюджет.

## Выбранный подход

Сохраняются существующие страницы, модели версий и история запусков. Интерфейс
использует метаданные запуска из сохранённой команды; старые снимки читаются без
миграции и перезаписи. Языковой контроль входит в валидацию structured output,
поэтому общий бюджет запросов не обходится отдельным циклом повторов агента.
Выбор модели в UI и общее переустройство страниц не добавляются.

Альтернатива только усилить промпт не гарантирует отказ от перевода. Полный запрет
повторного анализа мешает исправлению результата; выбран явный повтор с пояснением.

## Проверка

Поведенческие тесты открытия/повтора, различающихся версий/области/настроек,
идемпотентного повтора после сетевой ошибки и активного запуска; тесты языковой
валидации и ограниченных corrections; контекстный тест малого BRD целиком.
Затем полный quality gate, браузерная проверка и реальный локальный smoke.

## Уточнение интерфейса после просмотра результата

По замечаниям пользователя исходный текст показывается один раз в цитате источника,
без отдельного дублирующего раскрытия в колонке требования. Сведения о версии и SHA
раскрываются отдельно внутри цитаты. Если источник отсутствует, исходная формулировка
из результата анализа остаётся доступной рядом с предупреждением.

Загрузка перечисляет доступные расширения. На карточке документа виден выбор
последней версии для анализа, история остаётся для выбора других редакций. До выбора
документа кнопка неактивна и имеет нейтральный серый фон; рядом объясняется первый шаг.
Поле области анализа остаётся необязательным уточнением для модели под раскрытием
«Уточнить анализ», с пояснением поведения при пустом поле. Новый ввод обязателен
только по желанию пользователя; обычный анализ запускается с пустым уточнением.
