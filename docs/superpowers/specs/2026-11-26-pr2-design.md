# PR 2: воспроизводимое извлечение требований

Источник решений — BRD и существующие technical docs; границы уточнены заданием PR 2.
Оригинал, версия, сохранённые фрагменты и результат извлечения неизменяемы.
Загрузка новой редакции требует явного file_id. PostgreSQL хранит intent и метаданные,
локальное хранилище публикует проверенный временный файл без перезаписи.

RequirementsExtractionAgent получает только подготовленный ContextPack и типизированный
генератор. Выдаёт кандидаты требований, пробелов и противоречий; Application назначает
ID и проверяет цитаты относительно именно переданного контекста и версии.
Техническая проверка SourceRef не подтверждает смысл требования и не является approval.

StateGraph выполняет подготовку, извлечение частей, объединение, проверку и сохранение.
Checkpoint содержит идентификаторы и ссылки, предметные данные сохраняются отдельно.
SQL-идемпотентность защищает повтор узла. Выполнение не требует assistant message.
AsyncPostgresSaver создаётся и закрывается в управляемом lifespan; миграция — до readiness.

UI расширяет рабочее пространство документами и A-01 с историей запусков и источниками.
Чат, темы, архитектурные границы и quality gates сохраняются.
Оценка использует только исходные части reporting-system и BRD по эталонному шаблону.
Часть III example.pdf и expected-result.md никогда не становятся входом benchmark.

S3, OCR, RAG, согласование, редактор архитектуры, semantic diff и PR 3 вне объёма.
